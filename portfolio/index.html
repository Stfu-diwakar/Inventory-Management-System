ACID Transaction Lifecycle: Inter-Warehouse Stock Transfer

1
User Dispatches Transfer Streamlit UI passes source, target, SKU & quantity.
2
PL/SQL Row Lock `SELECT ... FOR UPDATE` locks source row to prevent concurrent race condition.
3
Debit & MERGE Credit Debits source facility; executes MERGE Upsert at target facility.
4
Atomic COMMIT Logs `TRANSFER_OUT` & `TRANSFER_IN` in stock ledger. Rollback on failure.

Procedural Database Logic

PL/SQL Stored Procedures & Triggers

Ensuring deterministic transaction isolation, preventing negative stock levels, and capturing tamper-proof audit trails at the database layer.

Row-Level Lock

SP_TRANSFER_STOCK

PL/SQL Stored Procedure • Atomic Transaction

Executes atomic inter-warehouse transfers. Locks the source row with SELECT ... FOR UPDATE to prevent race conditions, debits source stock, verifies available quantities, executes MERGE on target, and issues an atomic COMMIT or full ROLLBACK.

Oracle PL/SQL 
CREATE OR REPLACE PROCEDURE sp_transfer_stock(
    p_product_id   IN NUMBER,
    p_from_wh_id   IN NUMBER,
    p_to_wh_id     IN NUMBER,
    p_quantity     IN NUMBER,
    p_performed_by IN VARCHAR2,
    p_status       OUT VARCHAR2
) AS
    v_source_qty NUMBER;
BEGIN
    -- 1. Lock source row to avoid concurrency race
    SELECT quantity_on_hand INTO v_source_qty
    FROM INVENTORY
    WHERE product_id = p_product_id AND warehouse_id = p_from_wh_id
    FOR UPDATE;

    IF v_source_qty < p_quantity THEN
        RAISE_APPLICATION_ERROR(-20001, 'Insufficient stock');
    END IF;

    -- 2. Debit source warehouse
    UPDATE INVENTORY SET quantity_on_hand = quantity_on_hand - p_quantity
    WHERE product_id = p_product_id AND warehouse_id = p_from_wh_id;

    -- 3. Upsert target warehouse via MERGE
    MERGE INTO INVENTORY t
    USING (SELECT p_product_id AS pid, p_to_wh_id AS wid FROM DUAL) s
    ON (t.product_id = s.pid AND t.warehouse_id = s.wid)
    WHEN MATCHED THEN
        UPDATE SET t.quantity_on_hand = t.quantity_on_hand + p_quantity
    WHEN NOT MATCHED THEN
        INSERT (product_id, warehouse_id, quantity_on_hand)
        VALUES (p_product_id, p_to_wh_id, p_quantity);

    COMMIT;
    p_status := 'SUCCESS';
EXCEPTION
    WHEN OTHERS THEN
        ROLLBACK;
        p_status := 'FAILED: ' || SQLERRM;
END;
Autonomous Trigger

TRG_AUDIT_PRODUCT_CHANGES

Database Row Trigger • AFTER UPDATE / DELETE

Automatically fires whenever product unit prices or costs are modified. Archives historical pricing, modifier identity, and timestamps into the AUDIT_LOGS table, providing non-repudiation for fiscal audits.

Oracle PL/SQL 
CREATE OR REPLACE TRIGGER trg_audit_product_changes
AFTER UPDATE OF unit_price, cost_price ON PRODUCTS
FOR EACH ROW
BEGIN
    INSERT INTO AUDIT_LOGS (
        table_name,
        action_type,
        record_id,
        performed_by,
        action_date,
        details
    ) VALUES (
        'PRODUCTS',
        'UPDATE',
        TO_CHAR(:NEW.product_id),
        USER,
        SYSTIMESTAMP,
        'Price updated for SKU ' || :NEW.sku || 
        '. Old Price: $' || :OLD.unit_price || 
        ', New Price: $' || :NEW.unit_price || 
        ', Old Cost: $' || :OLD.cost_price || 
        ', New Cost: $' || :NEW.cost_price
    );
END;

Top Examiner Viva Questions & Model Answers

Model Answer: Oracle 23ai was chosen because enterprise supply chains demand industrial database features:

  • Fine-Grained ACID Concurrency: Oracle supports row-level locking via SELECT ... FOR UPDATE and multi-version concurrency control (MVCC) without blocking reads.
  • Native Procedural PL/SQL: Enables executing business logic (like stock balance validations and multi-warehouse debits/credits) directly inside the database kernel, avoiding network latency and distributed failure states.
  • Atomic MERGE (Upsert): Full support for ANSI-standard MERGE statements to atomically insert or update inventory in a single pass.
  • Enterprise Data Dictionary & Security: Deep metadata catalogs (USER_TAB_PRIVS_MADE, USER_CONSTRAINTS) that power our dynamic security console.

Model Answer: The schema strictly conforms to Third Normal Form across three validation stages:

  • 1NF (Atomicity): Every table attribute contains atomic, indivisible values. No repeating groups or array columns exist (e.g., individual order items are normalized into the separate ORDER_ITEMS relation).
  • 2NF (Full Functional Dependency): All non-key attributes are fully functionally dependent on the entire primary key. In composite-key associative tables such as INVENTORY (product_id, warehouse_id), attributes like quantity_on_hand depend on both keys, not just one.
  • 3NF (No Transitive Dependencies): No non-key attribute is dependent on another non-key attribute. For example, product category details (like category description) reside in CATEGORIES, not in PRODUCTS; supplier email and rating reside in SUPPLIERS.

Model Answer: The system enforces parameterized queries across all database service layers (dml_manager.py, query_service.py). User inputs are passed as positional or named bind variables (e.g., :p_sku, :p_price) to the python-oracledb driver rather than using raw string concatenation (f-strings). This ensures Oracle compiles the SQL execution tree first, treating user input purely as literal data values and rendering injection payloads inert.

Model Answer:

  • DELETE: A DML operation that removes rows individually, logs undo/redo data, can be rolled back, and fires database triggers. In our system, product deletions fire TRG_AUDIT_PRODUCT_DELETE to record who removed the item into AUDIT_LOGS.
  • TRUNCATE: A DDL operation that deallocates storage extents instantly, cannot be rolled back in most configurations, and bypasses all DML triggers. In our setup, TRUNCATE is reserved for administrative clean-slate re-initialization scripts.

Model Answer: The MERGE (Upsert) statement performs conditional conditional DML. When inventory is recorded for a product at a warehouse:

  • If a record already exists with matching (product_id, warehouse_id), Oracle executes the WHEN MATCHED THEN UPDATE branch to update quantity_on_hand.
  • If no record exists, Oracle executes the WHEN NOT MATCHED THEN INSERT branch to create a new row with identity key.
  • This executes in a single database round-trip without race conditions or client-side SELECT ... IF EXISTS logic.
